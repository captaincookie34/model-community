# Policy Packs

Policies and related prompts to be adapted and used with policy-following open safety models.

## Contributing

Before contributing a policy, we recommend reaching out by [opening an issue](https://github.com/roostorg/model-community/issues/new/choose) or chatting with us in [#model-community-rmc in our Discord server](https://discord.gg/UXmBqy7kFX) to make sure it's a good fit. Once you're ready to contribute, you can open a pull request to add your policies as Markdown files.

### Submit a pull request from GitHub on the web

If you are not familiar with the process of contributing to an open source project on GitHub, you can follow these directions. If you prefer to follow along with a video, here is a recording of the process:

[![Video thumbnail](thumb.png)](https://youtu.be/SqQdwlZla4w)

The process may seem long, but that's because we cover _every_ single step along the way; we promise it's not hard!

1. **Sign up for a [GitHub account](https://docs.github.com/en/account-and-profile) account**: Contributing currently requires an account with GitHub. We recommend choosing a username that will be recognizable or memorable as _you_ to others in the ROOST community, but you can also use a pseudonym.

2. **Navigate to the [policy-packs folder]** on GitHub if you're not already there. If your organization already has a folder, select that folder to navigate into it.

3. **Select `Add file ⏷` → `+ Create new file`** at the top-right of the page.

   1. **You may be prompted to "fork" the repository** to propose changes. If so, select `Fork this repository` to do so. 

   2. **If automatically creating a fork fails**, you can do so manually: visit the [model-community repository](https://github.com/roostorg/model-community), select `Fork` near the top-right, then select `Create fork` to confirm.

   3. **Return to the [policy-packs folder]** on the original repository and once again select `Add file ⏷` → `+ Create new file` to continue.

5. **Select the `Name your file…` text field** near the top of the page.

   1. **If this is the first policy from your organization**, type your organization name (lowercase, dash-separated) and then `/` to create a new folder for it. If you're already in a folder for your organization, skip this and continue to 4.ii.

   2. **Type a concise filename for your policy** (lowercase, dash-separated), ending with the `.md` file extension; for example, `tvec.md`. If you plan to contribute multiple related policies, you may use the same method as 4.i. to create a sub-folder, or just plan to name the files similarly (e.g. `tvec-definitions.md` and `tvec-actors.md`).

6. **Type or paste your policy** as [Markdown](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax) into the text area (where it shows `Enter file contents here`). To confirm the formatting is as intended, you may switch from `Edit` to `Preview` using the view switcher at the top.

7. **Select the green `Commit changes…` button** at the top-right to begin committing your changes.

8. **Enter a concise commit message** in the form: `policy packs: Add policy-name from your-org` (replacing `policy-name` and `your-org` as appropriate). Include any additional information that would be helpful to a reviewer in the extended description.

9. **Select `Propose changes`.** You'll see a comparison of of your proposed changes, but you're not done yet!

10. **Select `Create pull request`** near the top-right to begin opening a pull request. You'll see the same commit message and extended description from before pre-filled. Almost there!
   
   1. **If you plan to add additional policy files, change the title and description** to reflect all of the content you intend to submit, then next to the `Create pull request` button, select the `⏷` drop-down, and select `Create draft pull request` to signal that you have more to add.
   
   2. **Once you are happy with the pull request**, select the `Create pull request` or `Draft pull request` button to open a pull request.

If you're contributing one policy/file, you're all done! A member of the ROOST community will review your submission. Keep an eye on your [GitHub notifications] for any questions or changes requested. 

### Adding more files to your submission

If you would like to include additional files or policies in your submission, there are a few more steps to submit everything at once:

1. From your draft pull request, **select your fork's branch**, e.g. `yourname:patch-1` near the top, just under the pull request title. This will take you to your fork on GitHub, on the branch that contains your changes.

2. **Any changes made in this branch on your fork will automatically be included in the pull request.** Browse to the `resources`/`policy-packs`/`your-org` folder, then once again select `Add file ⏷` → `+ Create new file` to create any additional files.

3. **Once you've added all your files, return to your draft pull request and select `Ready for review`** to let the community know you've included all of your changes. Keep an eye on your [GitHub notifications] for any questions or changes requested!
